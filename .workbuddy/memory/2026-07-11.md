## 左侧目录树（Sider 导航）无法滚动修复
- 问题：BasicLayout 的 antd `Sider` 设了 `height:100vh` 但无 overflow，内部 Logo+Menu 无独立滚动容器；全局 `html,body,#root{overflow:hidden}` 又禁了整页滚动 → 菜单项超出视口即被裁掉且无法下滑。
- 修复（`web/src/layouts/BasicLayout.tsx`）：
  - Sider 加 `display:flex; flexDirection:column; overflow:hidden`
  - Logo 块加 `flexShrink:0`
  - 用 `<div className="sidebar-menu-wrap" style={{flex:1,minHeight:0,overflowY:auto,overflowX:hidden}}>` 包裹 `Menu`（关键 `minHeight:0` 才能让 flex 子项收缩出滚动）
- `web/src/styles/global-theme.css`：新增 `.sidebar-menu-wrap` 精致细滚动条样式（6px、hover 变主色）。
- `tsc --noEmit` 通过。

## 修正：为什么第一次改动没生效
- antd `Layout.Sider` 会把 children 包在内部 `.ant-layout-sider-children` div 里，把 flex 直接加在 `<Sider>` 根元素上**无法传递到真正的内容容器**，导致 `flex:1` 的菜单包裹层没有收缩、滚动条不生效。
- 正确做法：通过 CSS 把 `.main-layout .ant-layout-sider-children` 设为 `display:flex; flex-direction:column; overflow:hidden`，让 Logo 块与 `.sidebar-menu-wrap` 成为 flex 子项。
- 同时发现 Sider 自带底部折叠触发器（`collapsible`），点击后会把 Logo 文字挤成竖排（截图 2）。已把 `collapsible` 移除：顶部 Header 已有折叠按钮，底部触发器冗余且体验差。
- 折叠态 Logo 改为只显示 "AI"，避免 80px 宽度下文字换行。

## 手动拉起 Docker 栈 + 解决 8010 端口冲突（start.bat 二次复现 daemon 错误）
- 根因澄清：`start.bat` 再次卡在 [2/5] daemon not reachable，纯粹因为 **Docker Desktop 桌面程序没开**（与 MySQL/SQLite 配置无关——那个讨论只决定 Docker 起来后用哪个库，不会帮你启动 Docker 引擎）。
- 处理：手动启动 `C:\Program Files\Docker\Docker\Docker Desktop.exe`，引擎就绪（`docker info` 通过）。此前已构建的镜像被 Docker Desktop 自动把 api/worker/web/mysql/minio 全部拉起（mysql/minio 均 healthy）。
- 端口冲突：本地 SQLite 版 uvicorn 仍占 `127.0.0.1:8010`，与 Docker api 容器（`0.0.0.0:8010`）争用，127.0.0.1 流量被本地进程截走。已 `taskkill` 本地 uvicorn（PID 8676/11800），让 Docker 的 MySQL 后端独占 8010。
- 验证（确凿在 MySQL 上）：
  - api 容器 `DATABASE_URL=mysql://ai_agent:...@mysql:3306/ai_agent`
  - api 日志：`Detected database type: mysql` → `MYSQL database is ready!` → `Ensured database schema exists`
  - `mysql:3306 reachable`；web(:80) 与 api(:8010) 均 HTTP 200
  - worker 容器内 pymysql 实测 `PYMYSQL_CONNECT_OK`；早先 `Connection refused` 是 mysql 未就绪时的启动竞态（时间戳 13:29），13:30/13:31 重启后无新错误
- 访问地址：Web `http://localhost:80`（nginx 跑 dist）；API `http://localhost:8010`；前端 dev `http://127.0.0.1:5173`（现代理到 Docker 的 MySQL api）。
- 经验：本环境 Docker Desktop 不会自动随系统启动，daemon 需手动开；若本地先跑了 uvicorn，记得 kill 掉再起 Docker 栈，否则 8010 被截流。
