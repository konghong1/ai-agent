## 三次排错：AI 路径仍降级 = agnes-2.0-flash 是推理模型，max_tokens 太小把答案额度吃光

现象：第 2 次修复（兼容 AGNES_API_KEY）后，重新生成的记录仍 `prompt_source='template'`、`prompt_input`=真实配置、`prompt_raw=0`；api 日志 `POST apihub.agnes-ai.com ... 200 OK` 但 `AI 返回结构异常，降级模板引擎：''`。
根因（容器内真实调 agnES 抓包定位）：`agnes-2.0-flash` 是**带思维链的推理模型**——思考写进 `reasoning_content`、答案写进 `content`。原 `_chat_multimodal` 把 `max_tokens` 写死成 `1200`，思考过程占满额度后 `content` 为空串（`finish_reason:"length"`），代码读到空 → 降级。GET /models 确认 5 个模型：agnes-1.5-flash / 2.0-flash / image-2.0/2.1-flash / video-v2.0。

### 修复
- `AI_PROMPT_TIMEOUT` 90→120；新增 `AI_PROMPT_MAX_TOKENS=4096`（实测 `2048` 仍空、`4096` 稳定 `finish=stop` 且 content 有值）。
- `_chat_multimodal` 加 `max_tokens` 形参（默认 4096），不再写死 1200。
- `generate_prompt_via_ai` 改为重试（最多 3 次）：content 空/解析失败 → 上调 `max_tokens`(×2, 上限 8192) 重试；**成功或降级都保留 `prompt_input`(真实配置) 与 `prompt_raw`(最后一次原始返回)**，满足用户“把喂给 AI 的提示词和 AI 原始返回展示给我看”的诉求。
- 测试 `test_fallback_keeps_trace_placeholder` 对齐新行为（注入假 key 走真实降级留痕路径）。

### 验证（铁证）

## 聊天视频生成"生成不出来"排查 + 修复（12:23 轮）

用户现象：聊天里只输入提示词、没选参考图，视频生成不出来。

### 排查结论（关键：与"有无参考图"无关）
- 纯文本 t2v（无参考图）实测能提交且 Agnes `agnes-video-v2.0` 接受并 completed（progress=100）——缺图不是报错原因。
- 历史 2 条视频消息（MSG 12/14）均 `status=completed` + `reference_images=[]`，但 **blocks 里根本没有 `video_url` 字段**。
- 根因：Agnes 视频完成响应里，**真实播放 URL 在 `metadata.url`**（`https://platform-outputs.agnes-ai.space/videos/...mp4`），而
  `MediaService.get_video_status` 的 URL 提取只看顶层 `video_url/output/url/remixed_from_video_id`，**完全没读 `metadata.url`**
  → `video_url` 永远为空 → 前端 `MediaCard` 拿不到地址 → 视频放不出来（用户感知"生成不出来"）。
- 已排除：nginx SSE（`proxy_buffering off` + `proxy_read_timeout 86400s` 正确）、前端 watchVideo（正确传 provider_id + 解析 completed）、SSE 鉴权（`?token=` 兼容）、前端发送按钮 disabled 逻辑（不校验参考图）。

### 修复（`app/media.py` 的 `get_video_status`）
- 第一处（顶层 video_url 归一化）：候选列表改为字段**值** `[data.get("remixed_from_video_id"), data.get("output"), data.get("url"), (metadata or {}).get("url")]`。
- 第二处（raw_url 提取进 MinIO 存储）：增加 `(data.get("metadata") or {}).get("url")`。
- 效果：提取 `metadata.url`(Agnes CDN) → 下载存储到 MinIO → `video_url` 变成内部代理 `/api/media/assets/by-key/videos/2/...mp4`，前端稳定播放。

## 🐛 修复：worker "Can't reconnect until invalid transaction is rolled back"（20:20）

生成图片失败，worker 抛 `Can't reconnect until invalid transaction is rolled back`，被 `gallery_worker._process` 包成 `⚠ worker error`。

### 根因
- `run_gallery_task` → `_generate_one` 在子线程开会话 `s`，先 `s.get(rec)`/`s.get(user)` 开启事务，再调 `_real_generate(s, user, ...)`；`_real_generate` 内 `_resolve_image_model(s,...)` 又查库（事务保持打开），随后是 **数分钟阻塞的 HTTP 出图调用**（`MediaService.generate_image` timeout=300 + 重试）。
- 若此连接在长 HTTP 期间被服务端 `wait_timeout`/防火墙/瞬时 DBAPI 错误 `invalidate()`，回到 `s.commit()` 即抛「事务未回滚、无法重连」。
- 原 `except` 分支直接 `s.get`+`s.commit` 而不先 `s.rollback()`，无法自愈，异常经 `f.result()` 冒泡成 `worker error`。

### 修复
- `app/gallery_service.py` `_real_generate`：签名由 `(db, user, ...)` 改为 `(user_id, ...)`；模型解析改用语独立短生命周期会话 `with Session(engine) as rs:`，解析后立即关闭，**不在长 HTTP 期间持有事务/连接**。
- `_resolve_image_model`：参数 `user: models.User` → `user_id: int`（仅用 `user.id`，无跨会话 lazy-load 风险）。
- `_generate_one`：读取 `rec`/`user` 后先 `s.rollback()` 再发起 HTTP；`except` 分支先 `s.rollback()` 再重连写失败状态（核心自愈）。
- `app/core/database.py`：MySQL/PostgreSQL 引擎加 `pool_recycle=1800`（Docker 部署下回收空闲连接，源头减少失效连接）。

### 验证
- `py_compile` 两文件通过；`import app.gallery_service / app.core.database` 通过。
- 仅一个调用点（`_generate_one`）与 `_real_generate` 旧签名耦合，已同步改；`_resolve_image_model` 仅被 `_real_generate` 调用。
- `tests/test_gallery_prompt.py` 27 passed；`import` 冒烟测试 IMPORT_OK。修复闭环。
- 生效：`docker restart ai-agent-api`（bind mount 免 rebuild）。
