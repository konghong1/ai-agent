## 修复：聊天“无法连接到后端（加载消息 …/messages 失败）”是误导文案（用户质疑“为撒谎”）
用户报：打开某会话后消息加载不出来，弹 `无法连接到后端服务（加载消息 /api/threads/thread-8074015ec63d/messages 失败）。请确认后端已启动（端口 8010）`。

### 真相（nginx 访问日志 + curl 直连）
- `docker logs ai-agent-web` 显示该会话对**其主人（用户登录账号）返回 200 / 25KB**（如 `09:22:24 GET .../thread-8074015ec63d/messages?limit=20 200 25159`）。**后端活着且会话存在**。
- 我以 admin token 直连 `/api/threads/thread-8074015ec63d/messages` 返回 **404 `{"detail":"Thread not found."}`**：因为该会话属 konghong(uid=2)，admin(uid=1) 非主人被后端按 `user_id` 过滤——属正常权限隔离，非 bug。
- 结论：前端 `fetchLatest` 的 `catch` 把**任何 fetch 异常**（含网络抖动 / 请求被取消 AbortError）一律显示成“无法连接到后端服务（端口 8010）”，对 404 与瞬时中断都撒谎。用户质疑正确。

### 根因（为什么 fetch 会抛异常而非拿到 200）
- `fetchLatest` 本身无 AbortController，但当时后台正跑 `docker compose build`（因前次 `docker builder prune` 清空了 pip 构建缓存，本次从头下载 chromadb/langchain 等，16+ 分钟猛吃宿主机 IO/CPU）。api 容器那一瞬间响应超时 → 浏览器 fetch 抛网络异常 → 误报“后端挂了”。服务器恢复后 nginx 日志即见 200。属环境性瞬时抖动，非代码死 bug。
- 另：`fetchLatest` 的 `else` 分支（HTTP 4xx/5xx）其实已正确显示 `err.detail`（如 “Thread not found.”），只有网络/abort 类异常走 `catch` 才误报。

### 已修复（`web/src/pages/ChatInterface/index.tsx`，已 `npm run build` 重生 dist `index-BtKkjy6b.js`）
1. `fetchLatest` 增加 `AbortController`（`fetchAbortRef`）：每次发起新请求前主动 `abort()` 上一个在途请求；切换线程/卸载时的故意取消 → 抛 `AbortError` 在 `catch` 里**静默吞掉**，不再误报。
2. 三处 catch（`fetchLatest`/`fetchOlder`/`fetchThreads`）文案改诚实：
   - `e?.name === 'AbortError'` → 直接 return（不弹错）。
   - `e instanceof TypeError`（真网络层失败）→ `网络异常：加载消息失败（/api/threads/.../messages）。请检查网络或后端是否可访问`（不再武断“后端未启动”）。
   - 其它 → `加载消息失败：${e.message}`。
   - HTTP 4xx/5xx 仍走 `else` 分支显示 `err.detail`（如 “Thread not found.”）。
3. 卸载 cleanup 增加 `fetchAbortRef.current.abort()`，避免组件销毁后请求回来误弹错。

## 修复 localStorage 配额超限崩溃（chat-messages-cache）
