## 修复后端卡顿 & API 代理错误

### 问题
- Vite 代理报 ECONNREFUSED 127.0.0.1:8010
- 聊天时后端非常卡，视频生成后页面卡死

### 根因
`chat_stream` 端点的 `event_generator`（async def）中直接调用了三个同步阻塞函数：
1. `_handle_video_generation()` — requests.post, timeout=30s
2. `_handle_image_generation()` — requests.post, timeout=120s
3. `ask_agent()` — llm.invoke() 网络 + RAG 检索, 5~60s

在 async 函数中直接调用同步函数 = 冻结整个 asyncio 事件循环，导致服务器无法接受新连接。

### 修复
1. **app/api.py**: 三处调用用 `asyncio.to_thread()` 包装，移至线程池执行
2. **app/api.py**: 日志级别 DEBUG → INFO
3. **app/agent.py**: openai/httpx 日志级别 DEBUG → WARNING
4. **.env**: PORT 8000→8010（统一），LANGSMITH_TRACING true→false（API key 是占位符）
5. **.env.example**: PORT 8000→8010

### 注意
- 需要重启后端让 .env 变更生效
- watch_video_status 已正确使用 asyncio.to_thread，无需修改
- get_video_status 是同步 def，FastAPI 自动放线程池，无需修改

## 修复前端切换会话不生效

### 问题
用户在聊天界面切换会话时，会话不会变更（跳回原来的会话）。

### 根因
`handleSend` 中的 SSE 流可能持续 30 秒以上（视频生成更久）。SSE 完成后：
1. `setMessages(prev => [...prev, assistantMsg])` — 旧会话的回复被追加到新会话的消息列表
2. `setActiveThreadId(finalThreadId)` — 强制跳回原始会话，覆盖用户的切换操作

### 修复 (web/src/pages/ChatInterface/index.tsx)
1. 新增 `chatAbortRef` (AbortController) 用于取消正在进行的 SSE fetch
2. `selectThread` / `handleNewThread` / `deleteThread` 切换/新建/删除会话时：
   - abort 正在进行的 SSE chat stream
   - 关闭所有视频 SSE 连接 (esRef)
   - 清理重连定时器
3. `handleSend` 中 SSE fetch 加 `signal: abortCtrl.signal`
4. SSE 完成后检查 `activeThreadIdRef.current === threadId`，如果用户已切换会话则不追加消息、不覆盖 activeThreadId
5. catch 中处理 AbortError（静默返回，不显示错误）
6. 组件卸载时也 abort chat SSE

## 修复登录 500 错误 & 添加后端错误弹窗

### 问题
- 登录接口返回 500，Vite 代理报 ECONNREFUSED 127.0.0.1:8010
- 前端没有后端错误信息弹窗

### 根因
- 500/ECONNREFUSED 是后端热重载（--reload）期间的短暂问题，非持久性故障
- 前端 `fetch()` 在后端不可用时抛 `TypeError: Failed to fetch`，不是返回 Response，所以 `res.status === 0` 检查是死代码
- `request.ts` / `auth.ts` 没有 try/catch 包裹 fetch，网络错误直接抛原始 TypeError
- 各页面的 fetch 调用静默吞掉错误（`catch {}`），用户看不到任何提示
- 登录页的 antd `Form.Item name="mode" hidden` 触发了 React 警告
- 后端没有全局异常处理器，未捕获异常直接返回裸 500

### 修复
1. **web/src/services/request.ts**: 
   - `request()` 和 `upload()` 用 try/catch 包裹 fetch，捕获 TypeError 网络错误
   - 所有非 OK 响应都调用 `message.error()` 弹窗展示
   - 新增 `extractErrorMessage()` 统一提取后端错误信息
2. **web/src/stores/auth.ts**: login/register 用 try/catch 包裹 fetch，网络错误时抛中文提示
3. **web/src/pages/Login/index.tsx**: 
   - catch 中加 `message.error()` 弹窗
   - 移除 `name="mode"` 隐藏字段，改为 `onFinish={(v) => handleSubmit({...v, mode: 'login'})}`
4. **web/src/pages/ChatInterface/index.tsx**: 
   - `fetchThreads` / `fetchMessages` 从静默吞错改为 `message.error()` 弹窗
   - chat-stream catch 块也加 `message.error()` 弹窗
5. **app/server.py**: 添加 `@app.exception_handler(Exception)` 全局异常处理器，返回 JSON `{"detail": "..."}` 而非裸 500

## 二次修复：会话切换仍然不生效

### 问题
上一轮修复后用户反馈切换会话仍不生效。

### 根因（三个遗漏）
1. **切换时旧消息不清空** — `selectThread` 只调 `setActiveThreadId`，没有 `setMessages([])`。`fetchMessages` 是异步的，后端慢时旧消息一直显示，看起来像"没切换"
2. **`fetchMessages` 竞态条件** — 快速切换会话时，旧请求的响应可能在新请求之后返回，覆盖正确的消息列表
3. **`handleSend` 的 `setMessages` 无线程检查** — `setMessages(prev => [...prev, userMsg])` 没有检查当前线程是否已切换

### 修复 (web/src/pages/ChatInterface/index.tsx)
1. 新增 `fetchMsgIdRef` (useRef<number>) — 每次调用 `fetchMessages` 递增，响应返回后检查是否为最新请求，丢弃过期响应
2. 新增 `msgLoading` (useState<boolean>) — 加载消息时显示 spinner
3. `selectThread` / `handleNewThread` / `deleteThread` 中：
   - `setMessages([])` 立即清空旧消息
   - `fetchMsgIdRef.current++` 使所有进行中的 `fetchMessages` 请求失效
4. `fetchMessages` 中每次 `await` 后都检查 `reqId !== fetchMsgIdRef.current`，过期则 return
5. `handleSend` 中 `setMessages(prev => [...prev, userMsg])` 加 `activeThreadIdRef.current === threadId` 检查
6. 消息区域加 loading spinner（旋转圆圈 + "加载消息中..."）

## 三次修复：丝滑会话切换

### 问题
用户反馈切换会话仍不够流畅，要求"丝滑切换"。

### 根因（上一轮修复的遗留问题）
1. **`setMessages([])` 清空消息导致视觉闪烁** — 切换时先清空再加载，体验突兀

3. **`handleSend` 创建新会话时 `setActiveThreadId` 触发 useEffect → `fetchMessages` 覆盖刚添加的用户消息**
4. **全屏 loading spinner** — 切换时整个消息区被替换成转圈，不连贯

### 修复 (web/src/pages/ChatInterface/index.tsx)
1. 新增 `switchThread(threadId)` 包装函数 — 同步更新 `activeThreadIdRef.current` + `setActiveThreadId`，不再依赖 useEffect
2. 新增 `skipNextFetchRef` (useRef<boolean>) — `handleSend` / `handleNewThread` 创建新会话时设为 true，useEffect 检测到后跳过 fetchMessages，防止覆盖已有消息
3. 新增 `switching` (useState<boolean>) — 替代 `msgLoading`
4. `selectThread` 不再 `setMessages([])` — 旧消息保持可见，通过 CSS opacity+blur 过渡到新消息

6. `selectThread` 的 guard 改用 `activeThreadIdRef.current`（始终最新）而非 `activeThreadId`（可能 stale）
7. 所有 `setActiveThreadId` 调用替换为 `switchThread`
