# 2026-07-03 工作日志

## 任务一：视频加载状态优化

### 根因分析
SSE 端点 `watch_video_status` 的 `async def event_generator` 内直接调用同步 `requests.get`（15s 超时），
阻塞整个 FastAPI 事件循环，导致 SSE 事件无法推送，前端 EventSource 超时断开。
前端 `es.onerror` 直接关闭连接且无重连机制，视频永久卡在 "processing"。

### 修复内容
- **后端 `app/api.py`**: 用 `asyncio.to_thread()` 包装 `MediaService.get_video_status` 避免阻塞事件循环；
  首次轮询立即执行（不等待）；增加 SSE 心跳注释；修复 `remixed_from_video_id` 字段判断逻辑（仅当以 http 开头时作为 URL）；
  添加模块级 logger。
- **前端 `ChatInterface/index.tsx`**: 添加指数退避重连（2s→4s→8s→16s→32s，最大 5 次）；
  处理 processing 状态更新（显示 poll_count 进度）；超时后标记 failed；添加 `reconnectTimerRef` 管理重连定时器。
- **前端 `MediaCard/index.tsx`**: VideoBlock 接口添加 `progress` 字段；处理状态显示 "后台正在处理…（第 N 次状态检查）"。

## 任务二：知识库全流程重构

### 发现的 Bug
1. `or_` 未从 sqlalchemy 导入 — `_keyword_search` 运行时崩溃
2. 关键词搜索遍历字符串字符而非词 — `for w in query` 应为分词
3. `self.kb.rag_config` 不存在 — KnowledgeBase 模型无此字段
4. MMR 做 O(n²) embedding API 调用 — 极慢
5. ContextBuilder 和 RAG_SYSTEM_PROMPT 编码乱码（GBK→UTF8 mojibake）
6. CrossEncoder 每次检索重新加载模型
7. folder_id 元数据类型不匹配（int vs str）
8. ChromaDB 硬编码在所有服务方法中

### 修复内容
- **新建 `app/vector_store.py`**: 向量数据库抽象层，支持 ChromaDB/FAISS/Milvus 三种后端，通过 `VECTOR_STORE_BACKEND` 环境变量配置
- **`app/settings.py`**: 添加 `vector_store_backend`、`vector_store_path`、`milvus_host`/`milvus_port` 配置项
- **`app/models.py`**: KnowledgeBase 模型添加 `rag_config` JSON 字段
- **`app/core/database.py`**: 添加 SQLite 列迁移逻辑（`_migrate_sqlite_columns`）
- **`app/services.py`**: 
  - 修复 `or_` 导入
  - 关键词搜索用 `re.split` 正确分词
  - HybridRetriever 用 `self.rag_config`（从 kb.rag_config + DEFAULT_RAG_CONFIG 合并）
  - MMR 优化为批量 embed（O(n) API 调用）+ 向量化相似度计算
  - CrossEncoder 缓存（`_cross_encoder_cache`）
  - 所有 ChromaDB 调用替换为 `get_vector_store()`
  - ContextBuilder 和 RAG_SYSTEM_PROMPT 编码修复
  - 元数据 folder_id 统一存储为字符串
  - process_document 改为批量 upsert
