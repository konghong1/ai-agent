## Bug Fix: chat-stream 上游 API 404 错误

- **现象**: 发送聊天消息时 agnes API 返回 404 `NotFoundError: OpenAIException - {"detail":"Not Found"}`
- **根因**: `ask_agent()` 使用 `langchain.agents.create_agent()` 创建完整的 langgraph agent（含工具绑定、agent 专用 system prompt、消息格式转换），其构造的请求与 agnes API 不完全兼容。curl 直接调用 agnes API（含 tools 参数）正常 200，排除 API 不支持 tools 的可能。
- **修复**: `app/agent.py` 第 324-341 行，将 `create_agent() + agent.invoke()` 替换为 `llm.invoke()` 直接调用：
  - dict 消息转为 LangChain 消息对象 (SystemMessage/HumanMessage/AIMessage)
  - 直接 `response = llm.invoke(lc_messages)` 获取 AI 回复
  - `build_agent()` 不受影响，仍使用 `create_agent` 用于真正的 Agent 模式
- 影响范围: `/chat` 和 `/chat-stream` 两个端点均调用 `ask_agent`，均受益

- **方案**:
  - 后端新增 `GET /api/videos/{task_id}/watch` SSE 端点：内部每 2 秒 ping Agnes AI，推送 `data:` 事件（processing/completed/failed），完成时自动关闭 + 回写 DB。最多 150 次（5 分钟超时）。
  - 前端用 `EventSource` 替换 `setInterval`：消息出现 processing 视频 → 自动连接 SSE → 收到 completed/failed → 更新 state + 关闭连接。
  - 刷新体验：DB 已持久化 → 历史消息直接显示 completed + video_url，无需重新等待。
- **改动**: `app/api.py` +80 行（watch 端点），`ChatInterface/index.tsx` 轮询块替换为 SSE watch 块（净减 ~15 行）
