# 2026-07-06 修复 ai-agent-api / ai-agent-worker 容器启动失败

## 现象
两个服务起不来，反复重启。原始报错 `ModuleNotFoundError: No module named 'MySQLdb'`。

## 根因链（共 9 处问题）
1. **MySQLdb 缺失**：`docker/.env` 生成的 `DATABASE_URL` 是 `mysql://...`（无 driver），SQLAlchemy 默认走 `mysql+mysqldb`，需要未安装的 C 扩展 `MySQLdb`；`requirements.txt` 只装了 `pymysql`。
   - 修复：新增 `app/db_url.py: normalize_db_url()`，自动注入已安装的驱动（`mysql+pymysql://` / `postgresql+psycopg2://`），并在三处 `create_engine`（`app/core/database.py`、`app/db/__init__.py`、`app/worker/media_worker.py`）使用。
2. **worker `_parse_db_type` NameError**：模块级调用在定义之前（被 MySQLdb 崩溃掩盖的潜在 bug）。→ 把函数定义上移。
3. **API `init_db.py` 自导入**：`from .init_db import main` 应为 `from . import main`。
4. **schema 从未创建 / users 表缺失**：`main()` 只 seed 不建表；且 `docker/db/init_mysql.sql` 是个空目录（MySQL 忽略它）。
   - 修复：`main()` 增加 `create_tables()`（`Base.metadata.create_all`，幂等）；把空目录改成正常 SQL 文件。
5. **PostgreSQL 模型遮蔽 MySQL 模型**：`app/models/__init__.py`（UUID/JSONB，仅 PG）遮蔽了 `app/models.py`（MySQL），导致 `from app import models` 加载错误模型。
   - 修复：把 `app/models/` 重命名为 `app/models_pg/`，让 `app/models.py` 成为活动模块。
6. **`kb_documents` 索引超长**（MySQL 3072 字节限制）：`storage_path VARCHAR(1000)` 唯一索引超限。
   - 修复：改为前缀索引 `Index(..., mysql_length={"storage_path": 255})`。
7. **seed INSERT 失败**（`chunking_strategy` 无默认值）：裸 SQL 漏掉仅有 Python 端默认的列。
   - 修复：`seed_database()` 改为用 ORM 插入（自动套用模型默认值）。
8. **API 永远空命令重启**：compose 里 api 的 `command` 是折叠 `sh -c`，开头 `#` 注释把整条命令注释掉 → `sh -c` 啥也不干、退出码 0、Docker 无限重启、日志全空。
   - 修复：重写 api `command` 为干净的 `sh -c` 块（init_db 后 `exec uvicorn ... --reload`）。
9. **`media_assets` 表缺失**：`MediaAsset` 模型只存在于 PG 包。→ 移植 MySQL 兼容版到 `app/models.py`（String PK + uuid4 默认）。

## 验证
- `docker compose up -d` 后 5 个容器全部 Up：api / worker / web / mysql(healthy) / minio(healthy)。
- worker 在 14:27:44 后不再报 `media_assets` 不存在，现已静默运行（成功）。
- 关键一次性验证：`docker compose run --rm api python -m app.db.init_db` 成功建表+seed；`uvicorn app.server:app` 启动 `Application startup complete`。

# 2026-07-06（晚）修复聊天/提供商三个前端+后端 bug

## Bug 1：新增提供商拉取模型后只显示聊天模型（视频/图片不展示）
- 根因：后端 `app/api.py:_suggest_model_type()` 关键词启发式过弱，所有不匹配的模型都 fallback 成 `chat`；前端在添加提供商弹窗里把拉取的模型平铺展示（全部被标成"对话"），保存后视频/图片段的模型就空了。
- 修复：
  1. `app/api.py` 重写 `_suggest_model_type`（接受完整 model 对象，先信任 `type`/`category`/`capabilities` 字段，再按更广泛的图片/视频/嵌入关键词匹配），并在 `_fetch_models_from_api` 传入完整对象 `m`。
  2. `web/src/pages/ProviderManagement/index.tsx` 新增 `renderRemoteGrouped()`，把"从 API 获取模型列表"的模型**按 chat/image/video/embedding 分组展示**（弹窗内 + 提供商卡片内两处都用），视频/图片模型现在分区块可见，且每条可单独改类型。
- 验证：独立单测 16 个模型名全 PASS（dall-e/sdxl/flux→image，sora/hunyuanvideo/wan2/kling→video，bge/text-embedding/m3e→embedding，whisper→chat）；`py_compile` 通过。

## Bug 2：聊天页提供商为空时点击跳空白页
- 根因：`web/src/components/ChatSelector.tsx` 空状态 `navigate('/agents/providers')`，但 `App.tsx` 注册的路由是 `/providers`，导致跳到无匹配路由的空白页。
- 修复：改为 `navigate('/providers')`，并把空状态做成一个明显的虚线"请先配置 AI 提供商"按钮（hover 高亮、可点击跳转新增提供商）。

## Bug 3：聊天页没有提示词（prompt template）下拉框
- 根因：`ChatSelector` 在 `noProviders` 时直接 `return` 早退，把模板下拉框也一起藏了。
- 修复：把模板 `<Select>` 从早退分支里解耦，**始终渲染**（与提供商无关）；占位符改为"提示词"并区分有无模板。
- 配套：`app/db/__init__.py: seed_database()` 新增 5 条默认提示词模板（通用助手/代码专家/翻译官/写作助手/数据分析师），保证下拉框有内容。`python -m app.db.init_db` 已执行，DB 现有 5 条。

## 验证汇总
- 前端：`npx vite build` 成功（4274 模块，17.8s，无错）；`tsc` 仅报**历史遗留**无关错误（App.tsx/GlassButton/MCPManagement 等），本次改动文件（ChatSelector、ProviderManagement）无新增类型错误。
- 后端：`py_compile` 通过；`python -m app.db.init_db` 成功并建立 5 条模板。
- 注意：`import app.api` 在本机（系统 py3.10）因缺 `email-validator` 失败，属环境缺包，与本次改动无关。
