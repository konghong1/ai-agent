## 聊天流式输出 + 切页记录丢失修复（Task #72 · 已验证 PASS）
用户两个诉求：① 切换页面聊天记录丢失；② 聊天流式输出，字一个一个跳出来。

### 后端修复
- **`agent.py` 缺 `logger` 致 NameError**：`ask_agent_stream_gen` 里 `logger.error(...)` 但模块从未定义 `logger` → 异常被 NameError 掩盖。补 `logger = logging.getLogger(__name__)`。
- **`app/db/__init__.py` IndentationError（潜在部署炸弹）**：`wait_for_database` 的 try 块缩进错误，容器只靠旧 `.pyc` 缓存跑着，一次干净重启就会硬挂。修正缩进，`docker exec` `ast.parse` 确认 `PARSE_OK`，删旧 `.pyc`。
- **agnes 提供商流式行为关键发现**：agnes-2.0-flash 将**整个回答在一个 SSE delta 里一次性返回**（非逐 token），且首 token 延迟 ~16s（对新/旧线程均如此，是提供商家固有时延，非我方代码问题）。因此后端 `llm.stream()` 不产出增量 token，**前端打字机动画是唯一可见的"字一个一个跳"效果来源**。

### 前端实现（`ChatInterface/index.tsx`，6 处编辑）
- **打字机动画**：模块级 refs（`typewriterQueueRef`/`typewriterDisplayedRef`/`typewriterFinalRef`/`typewriterIdRef`/`typewriterThreadRef`/`typewriterTimerRef`）；`typewriterTick` 每 24ms 从队列取 `Math.max(1, ceil(q.length/28))` 字符追加到 assistant 气泡 content；`ensureTypewriter` 启动 interval；delta → 入队；answer → 设 finalRef + 队列空则立即 finalize、否则自然播完；卸载时 clearInterval。
- **切页记录不丢**：`useChatStore`(zustand 模块级) 内存缓存 byThread + `fetchLatest` 从 DB 重载 + `active-chat-thread` localStorage 持久化当前 thread → 组件 remount 时 hydrate(cache→DB)。

### 真机验证（Playwright，托管 node 22.22.2 + chromium-1228/chrome-win64/chrome.exe）
1. **持久化 PASS**：初始 20 bubbles(hasAgnes=true) → 切仪表盘 0 bubbles(activeThread 仍在 localStorage) → SPA 返回 20 bubbles(hasAgnes=true) → **全页 reload 20 bubbles(hasAgnes=true)**。JS Errors=0。
2. **流式+打字机 PASS**：发"请写一段关于秋天的八十个字左右的短文" → t=0-10s assistant 气泡空(等 LLM 16s 延迟) → t=11.5s firstNonEmpty len=4("秋风送爽") → t=12s len=47 → t=14s len=95(完整)。**打字机增长检测: YES**(4→47→95)。JS Errors=0。
3. **切页后持久化 PASS**：流式发送后切 dashboard → 返回 chat → reload → bubbles>0、lastLen=95 持续存在。

### 关键教训
- **Playwright 选择器坑**：`.msg-bubble` 的 innerText**包含其子级时间戳 div**，所以 `last()` 读到的是 "秋风送爽...7月19日 23:25" 而非纯消息文本 → 测量 len 时需 strip 时间戳正则 `/\s*7月\d+日\s*\d+:\d+\s*/`。
- **chromium 路径**：Win64 是 `chromium-1228/chrome-win64/chrome.exe`（非 `chrome-win`）。
- **antd 登录表单选择器**：`Input` 渲染为 `type="text"` 而非 `type="email"`；用 `placeholder` 选择器更稳：`input[placeholder="your@email.com"]` + `input[placeholder="请输入密码"]` + `button.login-btn`。
- **测试须等够 16s**：agnes 首响应 ~16s，之前"空气泡"全因测试只等了 6-8s。
