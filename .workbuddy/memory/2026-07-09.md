## 修复：聊天消息"从头部重载 / 不停刷新"问题（消息分页）

**现象**：打开/切换会话时整个消息列表全量重渲染，且 `useEffect([messages])` 无条件 `scrollIntoView` 把视图拉回底部 → 屏幕不停刷新、消息像从头部重载。

**根因**：`GET /api/threads/{id}/messages` 一次性返回全部消息，无分页；前端每切会话整段替换 + 粗暴自动滚动。

**改动**：
- 后端 `app/api.py:get_thread_messages`：新增 `limit`(默认20/上限50) 与 `before`(游标 message id) 参数，返回 `MessagesPage{messages, has_more, oldest_id, limit}`。基于 `(created_at, id)` 游标分页（新增 schema `app/schemas.py:MessagesPage`），兼容 MySQL/SQLite/Postgres，走 `ix_messages_thread_created` 索引。
- 前端 `web/src/pages/ChatInterface/index.tsx`：拆分 `fetchMessages` → `fetchLatest`(只取最新一页) + `fetchOlder`(上滚到顶加载历史并 prepend)；用 `scrollRef` 容器 + `handleMessagesScroll` 监听，接近顶部且 `has_more` 时加载更早；`useLayoutEffect` 通过 scrollHeight 差值保持上滚时的可视位置；去掉无条件 `scrollIntoView`，改为仅在初始加载或用户在底部且新消息到达时受控滚动。

**验证**：`tsc --noEmit` 通过；后端 `py_compile` 通过；SQLite 上用 95 条消息跑通游标分页（无重复/无缺口/正确终止）。

**注意**：返回结构由 `list[MessageRead]` 改为对象 `MessagesPage`，前端是唯一消费者（ChatInterface），已同步更新。

## 出网代理宕机导致视频生成一直失败（2026-07-09 09:17）
- **现象**: 日志持续 `ProxyError('Unable to connect to proxy', ... host.docker.internal:33210 ... Connection refused [Errno 111])`，视频状态轮询每 3s 刷屏，视频一直打不开。
- **根因**: `docker-compose.yml` 给 api/worker 注入 `HTTPS_PROXY=http://host.docker.internal:33210`（WorkBuddy 沙箱代理）。该代理随时可能拒绝连接；`requests`/`httpx`/`openai` 默认读此 env，代理挂掉即全部 `ProxyError` 硬失败，且无直连兜底。实测本环境宿主机可直连 `apihub.agnes-ai.com`（curl 返回 401，1.3s），代理 `33210` 当前拒绝连接 → 确属"代理单点 + 无兜底"。
- **修复**: 新增 `app/http_client.py` 韧性层（两层防护：①导入时探测代理，不可达则清 env 走直连；②`request_with_fallback`/`download_bytes_with_fallback` 每次出网带直连兜底+30s 宕机缓存）。接入 `media_retry.post_with_retry`、`media.py`/`media_new.py` 的 `get_video_status` 与 `_download_and_store`、LLM 客户端 `AsyncOpenAI(http_client=httpx.AsyncClient(proxy=None))`、`worker/media_worker.py` 的 `AsyncClient(proxy=None)`。
- **验证**: 设死代理后导入模块自动清 env，`request_with_fallback` 直连 apihub 返回 401（连接成功，此前必 ProxyError）。所有改动 py_compile + import 通过。
- **运维开关**: `DISABLE_PROXY_AUTOFALLBACK=1` 保留强制代理（仅代理-only 环境）。
