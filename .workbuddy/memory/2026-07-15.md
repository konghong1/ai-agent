## 修复：电商套图 SSE `/api/gallery/tasks/stream` 持续 401/422

### 现象
日志里 `GET /api/gallery/tasks/stream?token=...` 全部 `401 Unauthorized`（浏览器 EventSource 只能把 JWT 放 query，不能放 header）；偶尔同一路径带 `Authorization` 头时返回 `422 "stream" not int`。图片生成本身成功（agnes 上游），但前端进度推送连接一直 401，导致重连风暴。

### 根因 1（路由遮蔽，真 bug）
`app/gallery_routes.py` 里 `GET /tasks/{task_id}` 声明为 `@router.get("/tasks/{task_id}")`，**path 里没写 `: int`**。
Starlette 的路由正则取自 path 字符串，函数签名 `task_id: int` 不会把转换器写进 pattern，
于是 pattern 是 `[^/]+` 而非 `[0-9]+`，`/tasks/stream` 被 `/tasks/{task_id}` 抢先匹配（task_id="stream"）：
- SSE 没 header → 命中 `/tasks/{task_id}` 的 `get_current_user`（仅 header）→ 401。
- 带 header → 命中同路由，再 `int("stream")` 失败 → 422。
`app/deps.get_current_user_sse` 本就支持 `?token=`，只是被遮蔽从来没被执行到。

### 根因 2（为何单纯 restart 不生效，Docker 字节码陷阱）
Docker-on-Windows 把宿主源码 bind mount 进 `/app`，但镜像构建时预编译的 `.pyc` mtime 比挂载源码“新”，
Python 在 `PYTHONDONTWRITEBYTECODE=1` 下不重写但**仍读并信任陈旧 .pyc**，表现就是“改了后端代码 restart 不生效”。

### 修复
1. `gallery_routes.py`：`@router.get("/tasks/{task_id}")` → `"/tasks/{task_id: int}"`，PATCH 同理。pattern 变 `[0-9]+`，`/tasks/stream` 不再被遮蔽。
2. `app/deps.get_current_user_sse`：token 提取加 `or request.query_params.get("token")` 兜底（双保险）。
3. `docker/docker-compose.yml`：api 与 worker 启动命令开头加 `find /app -name '__pycache__' -type d -exec rm -rf {} + || true`，确保每次从最新源码编译。
4. 生效必须 `docker compose -f docker/docker-compose.yml up -d --force-recreate api worker`（**不是** `docker restart`——restart 仍跑陈旧进程/字节码）。

### 验证
重建后：`?token=` 与原 `Authorization` 头均 200；`/tasks/2` 返回 404（正确，说明真实 `{id}` 路由正常不被遮蔽）；nginx 入口 `?token=` 也 200；SSE 实际推送 keep-alive 帧。

### 注意
- 日志里的 `content_policy_violation`(400) 与 `image queue is full`(503) 是 agnes 上游的内容审核/限流，非本仓库 bug；现有重试逻辑已在处理并最终成功。
- 以后改后端代码，提醒用户用 `force-recreate`（或至少确认无陈旧 .pyc），否则现象诡异难查。

## 第二次优化：图片不显示根因 + 操作条 UI（资深开发介入）

### 现象
用户反馈：① 创作结果里「提示词 / 重作」两按钮排列丑；② 其他任务生成的照片显示不出来。

### 根因 1（后端缺陷，真 bug）— gallery_service._real_generate
本地下载图像（`_save_generated_image`）失败时，旧代码返回**上游远程临时 URL** 并标记 `completed`。
远程地址常因跨域 / 过期在浏览器加载失败 → 表现成「已完成却打不开的破图」。消费端 `run_gallery_task` 用 `if real and real.get("url")` 认可该 URL，故前端永远拿到打不开的图。
**修复**：下载失败不再返回不可显示 URL，改为 `return {"error": "图片已生成，但下载到本地失败…"}`；
消费端（~1559 行）`reason=(real or {}).get("error") or "出图失败…"`、`rec.status="failed"`、`result_url=None` → 根上杜绝「假完成真破图」。
> ⚠️ 该修复只影响**新生成**。存量记录需数据归一化（见下）。

### 根因 2（数据现状）— agent.db.gallery_records
17 条 completed 记录中：9 条 `/api/gallery/files/*.svg`（880B 离线占位图，能渲染为占位图形，非真破图）；
1 条 `picsum.photos` 真实可达图；**7 条伪造假地址**（`http://fake/result.png`、`https://example.com/fake*.png`）。
假地址经 `isRealImage` 放行 → 进 `PreviewableImage` → 加载失败 → 浏览器破图。
**数据归一化**（仅动明显伪造、只更新存在的列，agent.db 无 `error` 列故不写它）：
`status='completed' and result_url like '%fake%' → status='failed', result_url=NULL`（修 7 条）；本地/真实远程保留。

### 根因 3（前端健壮性缺失）
`PreviewableImage` 无加载失败兜底，远程失效即破图图标。
**修复**：
- `PreviewableImage` 新增 `errored` 态 + `onError`/`onRetry`/`erroredLabel` props；失败时渲染「破图降级卡」（斜纹底 + 图标 + 文案 + 可选「重新生成」按钮），替代浏览器破图。主网格用法传 `onRetry={()=>openRedo(rec)}`。
- 案例区裸 `<img>`（原图/缩略）加 `onError` 兜底换占位图。
- antd `<Image>` 加 `fallback` 透明像素防闪。

旧 `.cell-actions-row` 是「小紫胶囊 + 占满剩余宽度的描边按钮」→ 视觉失衡。

### 关键结论先说
之前两轮（SQLite 归一化 / _real_generate 兜底 / 前端降级）都只动了**本地 SQLite `agent.db`**，但**线上跑的是 Docker MySQL `ai_agent`**。两边是两套完全独立的数据。这是“为什么之前改了用户仍看不到图”的根本原因——改错库了。

1. `app/models.py`：`GalleryRecord.plan_item_id` 外键 `ondelete="CASCADE"` → `"SET NULL"`（plan_item 没了记录保留，图不丢）。
2. MySQL 实测执行：
   `ALTER TABLE gallery_records DROP FOREIGN KEY gallery_records_ibfk_2;`

### 必须记的硬教训
- **永远先确认线上用的是哪个库**：本仓库 `.env`(宿主)=`sqlite:///./agent.db`，但 `docker/.env`=`mysql://…ai_agent`。任何“改了数据用户看不到”都先 `docker exec ai-agent-api python -c "from sqlalchemy import text; ..."` 直查 MySQL，别在 SQLite 上白忙。

## 附带修复：gallery detail 路由 `{task_id: int}` 空格导致 404

`app/gallery_routes.py` 的 `GET /tasks/{task_id: int}` 与 `PATCH /tasks/{task_id: int}` 里转换器带**空格**（`{task_id: int}`），Starlette 路径转换器语法是 `{name:type}` **无空格**，带空格会被当成非法转换器 → 该路由实际不生效，`GET /tasks/26` 返回 Starlette 默认 404，`PATCH` 重命名任务也 404。SSE `/tasks/stream` 因 int 转换器不匹配 "stream" 故不受影响（200）。
**修复**：两处改为 `{task_id:int}`（去空格）。必须 `docker compose -f docker/docker-compose.yml up -d --force-recreate api`（清陈旧 .pyc）才生效；验证：detail GET 200、stream 200、list 仍含恢复记录。
> 顺带验证：列表端点 `GET /api/gallery/tasks`（前端创作结果页实际消费的数据）不受此 bug 影响，一直正常返回嵌套 records。
