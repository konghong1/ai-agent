## 一、来自设计稿本身的待确认项（设计系统文档已列出，我在此给出处理选择）

| # | 疑问 / 待确认 | 我的选择 |
|---|--------------|----------|
| Q1 | 品牌色（珊瑚红 `#FF4D2E`、AI 紫 `#7C3AED`、确认绿 `#C8E000`）为目测提取，需产品确认 | 按设计稿值实现，全部收口为 CSS 变量（前端）与配置常量（后端），后续改一处即可替换，无需改组件代码 |
| Q2 | 品牌名占位「智图 AI」 | 前端按设计稿展示占位名；后端不依赖品牌名，可配置 |
| Q3 | 图片为 picsum 占位、需联网 | 套图**业务数据**与生成结果全部走本地 SVG 占位（离线可验证）；示例展示(showcase)也用本地生成的 SVG，避免预览环境无网络时图片裂图 |
| Q4 | 移动端仅 ≤1080px 单列，完整移动端待设计 | 实现响应式：≤1080px 弹窗/栅格转单列；≤860px 隐藏侧栏（沿用应用布局）；完整移动端留作后续 |
| Q5 | 「另存为模板」原是 alert 占位 | **完整实现**：后端 `GalleryTemplate` CRUD + 应用模板 |
| Q6 | 「AI 帮填 / AI 帮推荐」原无实现 | 后端提供可插拔 `ai_fill` 接口，当前返回基于已填字段的**规则化建议**（如根据卖点自动补全通用设置），不接真实 LLM；接口形态预留，后续可替换为真实大模型 |
| Q7 | 活动海报特殊性（分辨率 selector 替代比例 dropdown） | 配置中 `hasResolution` 标记，前端按类型渲染不同控件 |

## 二、架构与扩展性决策（低耦合、高扩展）

| # | 疑问 | 我的选择 |
|---|------|----------|
| Q8 | 18 种策划类型及其字段如何避免硬编码、便于以后扩展？ | **数据驱动**：所有类型定义、个性化字段、下拉选项集中在 `app/gallery_config.py`，前端从 `GET /api/gallery/types` 拉取。新增一种类型 = 改一份数据，不动路由/组件 |
| Q9 | 后端如何解耦路由与业务？ | 经典分层：`gallery_routes.py`(仅 HTTP 参数/鉴权) → `gallery_service.py`(业务逻辑) → `models.py`(ORM)。路由不直接写 SQL |
| Q10 | 图片如何存储与回显？ | 本地落盘 `uploads/gallery/`，统一回显端点 `GET /api/gallery/files/{filename}`（防路径穿越）。不依赖对象存储，降低联调门槛 |
| Q11 | 生成（出图）如何保证可验证且不依赖外部 AI？ | `GalleryGenerationService` 可插拔：若配置了默认 image provider+model 则走 `MediaService` 真实出图；否则**离线生成 SVG 占位图**并落库为 `GalleryRecord`，保证端到端流程可验证。生成策略集中在一处，便于切换 |
| Q12 | 工作流模型（单项目 vs 多项目）？ | 每个用户维护一个「草稿(draft)」工作项目：`GET /api/gallery/projects?status=draft` 取最新，无则自动创建；「新建任务」创建新草稿。生成后项目状态 → generating → completed，并产出创作记录 |
| Q13 | 数据库兼容性 | 复用现有 `normalize_db_url` 与 MySQL 前缀索引约定；长文本/长路径用 JSON 列或前缀索引 |
| Q14 | 主题（亮/暗） | 暗色跟随应用级 `.dark` 类（BasicLayout 已有切换），套图 CSS 提供暗色变量分支 |

## 五、前端实现补充决策（本轮）

| # | 疑问 | 我的选择 |
|---|------|----------|
| Q15 | 参考图(`reference_images`)如何采集？后端 `reference_images` 存 filename 列表，但无独立上传端点 | 复用已上传的**产品图**作为参考图来源：弹窗内从 `project.images` 勾选，filename 写入 `reference_images`。不新增上传端点，避免与产品图混淆 |
| Q16 | 设计稿抽屉有「自定义子任务」选项卡，但后端类型固定 18 种 | 保留三选项卡视觉，但「自定义子任务」渲染为说明态（引导用户在「推荐类型」选择后在属性弹窗补充自定义要求），不伪造超出数据模型的类型 |
| Q17 | 生成结果预览 | 生成成功后弹出结果 Modal 网格展示 `result_url`；创作记录区独立展示历史 `GalleryRecord` |
